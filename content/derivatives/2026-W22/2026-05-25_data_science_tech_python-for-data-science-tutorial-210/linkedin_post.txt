Your CSV had ages stored as text. You summed them. Python returned "283542" instead of 105 — no error, no warning, just a wrong number in your report.

This is the bug that scares me more than any crash. A crash tells you something broke. A silent type error hands you a confident, plausible answer that happens to be wrong — and you ship it.

Here's the mechanism. Python is dynamically typed: you assign values, Python infers the type. Convenient, until a column you assumed was numeric arrives as strings from a CSV or API. Then "28" + "35" isn't 63. It's "2835". Concatenation, not addition. The interpreter is doing exactly what you told it — you just told it the wrong thing.

The fix is one habit. Any value from a CSV, API, or user input is a string until you prove otherwise. Check it, then convert explicitly:

raw_age = "28"
print(type(raw_age))  # <class 'str'>
age = int(raw_age)
print(age + 10)  # 38

Four conversion functions cover most of it: int(), float(), str(), bool(). Run type() on anything you didn't create yourself before you do math on it.

This isn't a Pandas problem you outgrow. Pandas hides it behind dtypes, but the same trap lives in object columns that should be numeric. Understanding what Python is actually holding is the thing that separates an analysis you can defend from one that falls apart the moment someone questions the number.

Types encode intention. Most silent bugs trace back to a programmer who didn't know what kind of thing they were holding.
