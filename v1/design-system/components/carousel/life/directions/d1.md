# D1 — "The Group Chat" — LOCKED TEMPLATE PACK

Native-UI mimicry. The essay lives inside an iMessage thread instead of under a caption — nobody
performs for a text message the way they perform for a photo with a scrim on it. The craft is in
the counterfeit: get the chrome exactly right (notch-safe status bar, contact header, asymmetric
bubble geometry, the tail on the last bubble in a run) so the forgery never announces itself.

## Visual language

- **Palette**: chrome `#F5F1EC` · outgoing bubble `#E8705A` coral / text `#FFFFFF` · incoming
  bubble `#E9E4DC` / text `#1E1B2E` · header divider `#DDD6CC` · signature bubble fill `#FBEAE3`,
  border `#F0CFC2`, text `#B34A38` · muted meta text `#9C9284` / `#B0A695`.
- **Fonts**: chat copy in the **system stack** (`-apple-system, BlinkMacSystemFont, "SF Pro Text",
  "Helvetica Neue", Arial, sans-serif`) — never a "designed" typeface, that would break the
  illusion instantly. Lora Italic 600 appears exactly ONCE per slide, max, inside the single
  distinguished "unsent thought" bubble. Nunito Sans 700/800 handles header/meta/labels only.
- **Ground**: always the light Messages chrome (`#F5F1EC`). This direction has no dark variant —
  the whole point is the ordinariness of a daylight phone screen.

## How these templates work (read before generating)

1. Every template below ships as a complete markup block + the CSS it needs. Use it EXACTLY — only
   fill the `<!-- SLOT: ... -->` comments with real copy. Do not drop the status bar, the contact
   header, the bubble tail radii, or the typing-indicator footer to make a slide "simpler."
2. **Coral is the only outgoing-bubble color.** Never recolor an incoming bubble, never use coral
   for body-text emphasis outside a bubble fill — the iOS blue-bubble instinct is the entire
   mechanism and it only works if coral does exactly that one job.
3. The Lora-italic signature bubble (see BODY: Unsent Thought below) is the ONE literary intrusion
   per slide, max — never two signature bubbles on the same slide, never on the hook slide (the
   hook should read as an ordinary exchange, the signature bubble is a mid-deck reveal device).
4. Real threads don't make every bubble outgoing. Alternate in/out realistically — at least one
   incoming bubble per slide unless the beat specifically calls for an unanswered outgoing bubble
   (see BODY: Read Receipt below, where the silence IS the content).
5. Bubble copy across a slide (all bubbles combined) still obeys the system's per-slide word caps:
   hook headline = the outgoing hook bubble(s), 5-8 words hard cap; every other slide's combined
   bubble text stays under 30 words.

## Chrome mapping (contract elements re-skinned natively)

The generator contract's required overlay elements (`progress-row`/`progress-seg`/`fill`,
`counter-chip`, `follow-tag`, `save-tag`, `cliffhanger`, swipe arrow) are never pasted on top of
this thread as generic corner pills — a text-message screen doesn't have HUD chrome. Instead each
one is folded into a piece of chrome the Messages app would actually show. **The required class
name always stays on the element** (so the export pipeline can still find and fill it) even though
its position and styling are native to this world, not the four-corner generic layout:

- `.progress-row` / `.progress-seg` / `.fill` → a hairline hidden in plain sight: a thin tick strip
  sitting just under the status bar, barely visible, the way iOS itself sometimes shows a subtle
  loading/sync indicator. Never a bold bar.
- `.counter-chip` → the small gray line under the contact name in the header (where "1 of 9"
  already lives natively) — normal flow, not absolutely positioned.
- `.follow-tag` → a small coral pill in the header's top-right, styled like a native "Add Contact"
  affordance. **CTA slide only.**
- `.save-tag` → a small coral-outline pill near the footer, opposite the typing indicator. **Hook
  slide only.**
- `.cliffhanger` → wraps the typing-indicator bubble AND the teaser line together as one footer
  unit — the three dots ARE the suspense, the teaser text is the required copy. Every slide except
  the last.
- swipe arrow → the small dark circle already living inside the footer's teaser line; add
  `class="swipe-arrow"` to it. Every slide except the last.

## Rules

- System font for every bubble; Lora Italic 600 only inside `.sig` (max one per slide, never on
  the hook or CTA slide).
- Coral (`#E8705A`) only fills outgoing bubbles, the follow-tag pill, and the sig accent text —
  never a body background, never a doodle, never a highlight span.
- Status bar → header → thread → footer, always in that order, always present, never cropped.
- Real threads alternate in/out; only the Read Receipt Beat template is allowed to break that rule.
- Combined bubble word count per slide: hook ≤ 8 words (outgoing bubbles only), every other slide
  &lt; 30 words across all bubbles.
- `.progress-row`, `.follow-tag`, `.save-tag`, `.cliffhanger`, swipe-arrow classes must be present
  per the per-slide-role rules (save-tag hook-only, follow-tag CTA-only, cliffhanger every slide
  but last) even though their position/styling is native to this chrome, not the generic corners.
