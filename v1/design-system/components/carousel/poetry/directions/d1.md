# Poetry Carousel — Direction D1: "Draft, Unsent" — LOCKED TEMPLATE PACK

Base philosophy: the poem as an actual unsent iOS Notes draft, not a design *about* a poem. The
audience is looking over someone's shoulder at their Notes app — a struck-through word, a
highlighted phrase, a blinking cursor, a glimpsed keyboard. Total interface fidelity is the craft;
nothing is stylized for poetry. Gold is the color of revision and a second thought, never a flat
decoration.

## Visual language

- **Palette**: aged gold `#B89850` (primary UI accent), `#8A6E30` (dark gold, revision/edit color)
  against near-white "screen" `#FFFDF8` and warm parchment `#F6F1E4` (the carousel-chrome margin
  visible around the phone screenshot). Ink `#221D14` / `#3A3428` for real text; muted taupe
  `#B7A98A` / `#C7BC9E` for timestamps, disabled UI, and struck-through text.
- **Fonts**: iOS system font stack (`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Helvetica
  Neue", sans-serif`) for ALL in-app text (note title, body, status bar, navbar) — this is the
  interface-fidelity rule, never swap in Playfair Display inside the phone screen. `DM Sans` only
  for the carousel-system chrome band (progress row, counter, handle, follow-tag, cliffhanger).
- **Ground**: every archetype renders as a real phone screenshot — status bar (9:41, signal,
  battery), Notes navbar (`‹ Notes` / `Aa ⋯` or `Done`), a 1px hairline `#EDE4D0` under it, then
  content on `#FFFDF8`. A thin `#F6F1E4` margin band above the phone (0–36px) carries the carousel
  system chrome, separate from the phone's own fake status bar — do not merge the two bands.

## How these templates work (read before generating)

1. Every archetype below ships as a complete markup block + the CSS it needs. Use it EXACTLY —
   only fill the `<!-- SLOT: ... -->` comments with real copy. Do not drop the status bar, navbar,
   hairline, cursor, keyboard, or any other signature element to make a slide "simpler" — the
   forensic screenshot fidelity IS this archetype; a plainer version breaks the illusion.
2. The **shared overlay chrome** (progress row, counter, handle, follow-tag, swipe-arrow, save-tag,
   cliffhanger) is defined once below — include it, verbatim, on every slide. Which of
   follow-tag / save-tag / cliffhanger actually renders on a given slide still follows the main
   system prompt's per-slide-role rules (badge + handle always; follow-tag CTA-slide only; save-tag
   hook-slide only; swipe-arrow every slide but the last; cliffhanger every slide but the last).
3. Never let Playfair Display, gold-leaf, or any other niche's ornament leak into the phone screen
   — the entire point of this direction is that it reads as a real, boring productivity app.
4. Alternate footer-present archetypes (Edited Stanza, CTA) with footer-absent ones (Selection
   Highlight, Share Sheet, Voice Draft, Second Draft) so the bottom chrome doesn't repeat twice
   running — see the `clear-footer` note on `.cliffhanger`.

## Rules

- **Hook headline** = the note's opening line, &le;8 words. If the poem's real first line runs
  longer, use a trimmed fragment rather than wrapping — a note app doesn't wrap a headline.
- **Body word cap**: the generic &lt;30-word system cap applies only to *commentary/gloss* text
  (dictation label, sheet actions, version chip). Verse lines inside `.body`/`.noteTitle` flow at
  their natural stanza length — do not truncate a real line of the poem to hit a count.
- Never use Playfair Display, gold-leaf, or ornament inside the `.phone` — the entire direction
  depends on reading as an unstyled, boring, real app.
- Alternate footer-present (Edited Stanza, CTA) and footer-absent (Selection Highlight, Share
  Sheet, Voice Draft, Second Draft) body archetypes so the bottom third doesn't repeat.
- Per the main system prompt, no two adjacent slides may reuse the same archetype; hook and CTA
  slides intentionally share the Edited-Stanza register so they read as two frames of one document.
