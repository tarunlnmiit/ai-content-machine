# D3 — Root Access — LOCKED TEMPLATE PACK

Terminal noir: the feedback doc as raw log output, `grep`-ed out of a file, not written as a
memo. A convincing terminal window — traffic-light chrome, a tab title, a real `$` prompt in the
muted green every shell theme converges on — rendered with the exact proportions of a tool this
audience lives inside eight hours a day. Color obeys terminal convention, not brand convention:
dim gray for structure, desaturated green for affirmation, desaturated rose for the flagged line.
The signature move is slide 4's diff: the "memorized it vs. owned it" contrast rendered as a
literal git-style diff block, because for this content the metaphor and the form are the same
thing.

## Visual language

- **Palette**: ground `#0D0F14`, panel `#14171D`, chrome border `#1E222A`, ink `#C9CCD1` /
  bright `#F1F3F5` / dim `#6B7078` / dimmer `#3A3F47`. Brand blue survives only as the prompt
  accent and cursor glow (`#6B8FA8`/`#96BAD0`). Terminal-convention green `#4B8C6E`/`#4B7360` for
  affirmation and diff `+`; terminal-convention rose `#C4636B`/`#D98A90` for the flagged line and
  diff `-`. Traffic-light dots use their real macOS colors (`#FF5F57`/`#FEBC2E`/`#28C840`) — these
  are chrome, not content, and are the one place pure red/yellow/green is correct because it is
  copying a real window control, not making a semantic claim about the content.
- **Fonts**: 'JetBrains Mono', monospace — everything, no exceptions. A terminal that switches to
  a sans headline stops being a terminal.
- **Texture**: none beyond the window chrome itself (winbar, status bar, line numbers, cursor
  block). A terminal's authenticity comes from a hundred small correct proportions, not decoration
  layered on top.

## BODY TEMPLATES (5 — never reuse the same one on two adjacent slides)

### 1. Git Diff (the mockup's own body — the direction's signature)

Use ONLY when the content is a genuine before/after or comparison — this is the archetype the
whole direction was built to earn.

```html
<div class="slide">
  <div class="winbar"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="wintitle"><!-- SLOT: e.g. "diff — candidate_042.review" --></span></div>
  <div class="statusbar"><span class="counter-badge"><!-- SLOT --></span><div class="progress-row"><!-- SLOT --></div></div>
  <div class="review-head"><!-- SLOT: e.g. "review: panel_042 · 2 comments" --></div>
  <div class="diff">
    <div class="diff-line minus"><span class="gutter">−</span><span class="linenum"><!-- SLOT --></span><span class="code"><!-- SLOT: before line --><span class="inline-comment">// <!-- SLOT: inline gloss --></span></span></div>

  </div>
  <div class="cliffhanger"># <!-- SLOT: teaser micro-line --></div>
</div>
```

## Rules

- Every slide keeps the winbar's three traffic-light dots and the status bar — never simplify a
  terminal to just the body text, that reads as a code block, not this archetype.
- Only use the Git Diff archetype (#1) for genuine before/after content — do not force a diff onto
  content that isn't actually a comparison.
- Red/green is sanctioned ONLY inside the Git Diff archetype's `.diff-line.minus`/`.plus`; every
  other archetype in this pack uses terminal gray/green/rose per the palette above, never a raw
  red/green pair.
- Hook headline: 5-8 words, hard cap, split across `.out-line` divs as needed.
- Body copy per slide: under 30 words total.
- Never use the same body template on two adjacent slides.
