The bug that ate a Saturday

MLflow logged to a relative path. Cron runs from $HOME.

Every run showed green. Metrics logged fine. Then the scheduler quietly wrote a second ./mlruns tree from a different working directory. No error. No warning.

The tell: predictions never changed, even as fresh runs kept appearing in the UI.

The fix — one assert

Absolute paths in one .env the cron sources, plus a startup check that fails loud instead of failing silent:

# both training and serving MUST resolve here ARTIFACT_ROOT = Path(os.environ["MLFLOW_ARTIFACT_ROOT"]).resolve() assert ARTIFACT_ROOT.is_absolute() assert ARTIFACT_ROOT.exists()

The thesis

A config that silently does nothing is worse than one that errors.

Kubernetes wouldn't have made one prediction more accurate. It would've handed me a second system to babysit. Go count your predictions per day — that number tells you how much machinery you're allowed to skip.
